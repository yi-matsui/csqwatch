# 設計メモ

Author: yuichi(作成 2026-10-10 / 更新 2026-10-28)

関数ごとの役割は [functions.md](functions.md)、AT コマンドは [at-command-table.md](at-command-table.md) を参照してください。

## データの流れ

```
Monitor.bat ─► Monitor.ps1
                 │  起動時: 二重起動の確認 (動いていれば監視画面を前面に出して終了)
                 │          監視画面を開く (Browser.ps1)
                 │
                 └─(1 秒ごとにループ)─┐
                    ├─ 5 秒ごと                   → 受け取り先に csqwatch_calltable*.json があれば取り込む
                    ├─ タイムテーブルの時刻       → "AT+CSQ" → AtIo.exe ... "ATD<番号>;" <秒> "ATH" "AT+CSQ" <間隔> → "AT+CSQ"
                    └─ 周期ごと                   → AtIo.exe ... "AT+CSQ" / "AT+CREG?" / $Extras
                         │
                         ├─► logs/csq_YYYYMM.csv      追記 (月別。取得結果)
                         ├─► logs/call_YYYYMM.csv     追記 (月別。発信試験の結果)
                         ├─► CallTable.json           タイムテーブル (取り込んだとき)
                         ├─► logs/test_YYYYMMDD.log   追記 (日別。試験ログ)
                         ├─► data.js                  毎回まるごと書き換え (一時ファイル → 置換)
                         └─► trend.js                 10 分ごと。$TrendDays 日分を 15 分ごとにまとめたもの

index.html ──(3 秒ごと)── <script src="data.js?t=…"> を差し替えて読み込み → カード・グラフ・発信試験の表を更新
index.html ──(「保存」)──► ダウンロードフォルダ\csqwatch_calltable.json  (Monitor が取り込む)
```

## 設計判断

### HTTP サーバを使わない

画面は `file://` で開く静的な HTML です。データは JSON を `fetch` せず、**`<script>` タグで `data.js` を読み込みます**。
`fetch` は `file://` では CORS 制約で失敗しますが、`<script>` の読み込みは制約を受けません。
HttpListener による常駐サーバ(ブロッキング、CORS、エンコードの問題)が丸ごと不要になります。
URL にクエリ(`?t=…`)を付けてキャッシュを避けています。Edge・Chrome・Firefox のどれでも同じように動きます。

### C# は I/O だけ

`AtIo.exe` は `AtIo.exe <Port> <BaudRate> <Cmd> [WaitSec] [AfterCmd] [DuringCmd] [DuringEverySec]` で動き、応答を標準出力へそのまま出します。
コマンドの種類・応答の解釈・周期などの知識は持ちません。**C# を書き換える必要が出るのは、シリアル通信そのものを変えるときだけ**にしています。

- 接続は 8N1、DTR/RTS を ON にして開き、開いた直後に `ATE0V1`(エコー OFF・文字応答)を送ってから、その応答を捨てます。
- `AfterCmd` なし:応答の終端行(`OK` / `ERROR` / `NO CARRIER` / `+CME ERROR: n` など)を受信した時点で終了。`WaitSec` は上限です。終端は、これまでに受信した全文に対して判定するので、応答が途中で分割されても取りこぼしません。
- `AfterCmd` あり:`WaitSec` 秒間受信を続け、その後 `AfterCmd` を送ります。試験発信(`ATD…;` → 呼出 → `ATH`)用です。
- `DuringCmd` あり(`AfterCmd` と一緒のときだけ):`Cmd` の終端行を受信したあと、`DuringEverySec` 秒(既定 5、最小 2)ごとに `DuringCmd` を送ります。発信試験の通話中の `AT+CSQ` 用です。
  - `Cmd`(`ATD`)の応答前には送りません。V.250 では、コマンドの実行中に文字を受け取ると実行を打ち切る機器があり、発信が中断されるためです。`ATD` に応答がなければ、通話中のコマンドは一度も送りません。
  - 待ち時間の残りが 2 秒未満なら送りません(`AfterCmd` の直前に応答が重ならないように)。
  - `NO CARRIER` / `BUSY` / `NO ANSWER` / `NO DIALTONE` を受信したら、待ちを打ち切って `AfterCmd` に進みます。
  - 区切りとして、送る前に `--- during <コマンド>`、`AfterCmd` の前に `--- after <コマンド>` の行を標準出力へ出します。PowerShell 側はこれで「`ATD` の応答」「通話中」「切断」を分けます。`DuringCmd` を使わないときは区切りを出さないので、従来の出力と変わりません。
- 終了コード:`0` 正常、`1` 引数不足、`2` I/O エラー(エラー内容は標準エラー出力に `IO Error: …` で出す)。

### COM ポートは開きっぱなしにしない

`AtIo.exe` は AT コマンド 1 回ごとに起動し、COM ポートを「開く → 送受信 → 閉じる」で終わります(1 回の取得で `AT+CSQ` と `AT+CREG?` の 2 回)。
周期の合間はポートが空くので、プロセスがポートを握り続けることがありません。
試験発信だけは、`ATD` から `ATH` までを 1 回の起動の中で行い、通話中はポートを開いたままにします。

### 取得のリトライはしない

`AtIo.exe` が失敗しても、その周期では再送しません。失敗として CSV と試験ログに記録し、次の周期(既定 180 秒後)に取り直します。
リトライを入れると失敗が見えにくくなるため、まず試験ログで失敗の頻度と傾向を確かめる方針にしています(警報のための「連続失敗回数」の考え方は今後の課題)。

### 収集ループは 1 秒刻み

取得周期(既定 180 秒)の間も、1 秒ごとに時刻を確認します。定時発信の `HH:mm` を取りこぼしません。
同じ分に 2 度発信しないよう、`yyyyMMdd_HHmm` をキーにして制御しています。発信の直後には、すぐに 1 回取得します。
次の取得は「前回の取得が終わってから `$PollSec` 秒後」です。取得にかかる時間の分だけ、時刻は少しずつ後ろにずれます。

### 入口は Monitor.bat ひとつ(二重起動の防止)

輪番で運用する人が覚えることを減らすため、入口を `Monitor.bat` ひとつにしています。

- 起動時に名前付き Mutex(`Global\CsqWatch`。`-Mock` は `Global\CsqWatch_Mock`)を取ります。`Global` 名前空間なので、別のユーザーでログオンして起動した場合も検出できます。
- 取れなかったとき(すでに動いているとき)は、監視を始めずに監視画面を前面に出し(閉じていれば開き)、5 秒後に終了コード `3` で終わります。`Monitor.bat` は終了コード `3` のときだけ `pause` せずに閉じます。
- 前回の Monitor が異常終了していた場合は、Mutex の放棄(`AbandonedMutexException`)を受け取って普通に起動し、試験ログに WARN を残します。
- 動いている Monitor の情報(PID・開始時刻・ユーザー・PC 名)は `logs\monitor_running.txt` に書き、Ctrl+C で止めたときに消します。

### 社外監視の窓を最優先にする

この PC では、社外監視(VPN 経由の衛星事業者のダッシュボード)の窓が最優先です。監視画面はそれに影響を与えないように開きます(`Browser.ps1`)。

- 社外監視とは別のブラウザを選びます(`$Browser = 'auto'` は Chrome → Edge の順。Firefox は他業務で使うので `auto` に含めない)。
- 専用プロファイル(`app\profile_<ブラウザ名>`)で起動するので、社外監視のブラウザとはプロセスが分かれます。こちらが重くなっても落ちても巻き込まず、Cookie やログイン情報も共有しません。
- Chrome・Edge はアプリモード(`--app`)で開き、タブのない専用の窓にします。
- すでに開いていれば、専用プロファイルで動いているブラウザの本体プロセスを探し、その**プロセス ID を指定して**前面に出します(`WScript.Shell` の `AppActivate`)。窓のタイトルで探さないので、社外監視の窓を動かすことはありません。
- Monitor は CPU 優先度「通常以下」(`BelowNormal`)で動き、子プロセス(`AtIo.exe`・監視画面のブラウザ)もそれを引き継ぎます。
- Monitor と監視画面はローカルのファイルだけで動き、ネットワークを使いません。

### 取得失敗と圏外を分ける

端末が値を返さなかったこと(COM のエラー・無応答)と、端末が「圏外・測定できない(`99`)」と返したことは、運用上の意味がまったく違います。

| 状況 | `CsqOk` | 画面 | グラフ | CSV の 3 列目 |
|---|---|---|---|---|
| 端末が値を返した | `true` | 値と `値 / 最大値` | その値 | `値 / 最大値` |
| 端末が `99` を返した | `true` | `圏外 (99)` | 0 | `圏外` |
| 取得失敗 | `false` | `--` と赤の `取得失敗` | 線が途切れる(`null`) | `取得失敗` |

### 信号の目盛りは機器ごとに設定する

`AT+CSQ` の rssi の範囲は機器によって違います(GSM は 0〜31、IsatPhone 2 は 0〜55)。GSM の dBm 換算(`-113 + 2 × rssi`)は GSM 以外では意味を持たないので使わず、生の値を `値 / 最大値` で表示します。最大値は `Config.ps1` の `$RssiMax` で、グラフの縦軸もこれに合わせます。

### 発信試験はタイムテーブルで動かし、画面で編集する

- タイムテーブルは 24 行(各時 1 行)。行ごとに時刻・番号・ON/OFF、全体に「有効」と呼出秒数を持ち、`app\CallTable.json` に保存します。
- **画面は `file://` の静的な HTML なので、ファイルを直接書けません。** そこで画面の「保存」は `csqwatch_calltable.json` をダウンロードとして保存し、Monitor が 5 秒ごとに受け取り先(既定はログオン中のユーザーのダウンロードフォルダ。`$CallTableInbox` で変更可。`app\` も見る)を探して取り込みます。Web サーバを置かない方針を保ったまま、人の手でファイルを移す手順をなくしています。
- ブラウザはダウンロードの途中は `.crdownload` / `.part` などの別名で書くので、書きかけのファイルを取り込むことはありません。同じ名前が続くと `csqwatch_calltable (1).json` のようになるので、`csqwatch_calltable*.json` の中で最も新しいものを取り込み、ほかは古いものとして扱います。
- 取り込む前に、24 行あるか・時刻の形式・ON の行どうしの時刻の重なり・番号の形式(`+` と数字 3〜20 桁。空白とハイフンは除く)・呼出秒数(5〜120)・発信してよい番号(`$CallNumberAllow`)を確かめます。1 つでもおかしければ**全体を取り込まず**、前のタイムテーブルのまま理由を画面と試験ログに出します。画面側でも保存の前に同じ確認をします。
- 取り込んだファイルは `logs\calltable_history\日時_ファイル名` へ移します(取り込めなかったものは末尾に `.rejected`、古いものは `.old`)。いつ・どう変えたかの記録になります。
- 画面は、保存したタイムテーブルの `savedAt` と、`data.js` の `call.savedAt`(取り込み済み)・`call.rejectedSavedAt`(取り込めなかった)を比べて、「反映済み」かどうかを出します。
- `CallTable.json` が壊れていて読めないときは、上書きせずに残し、発信試験を止めた状態で動きます。
- `CallTable.json` がまだないときは、各時 01 分・番号 `$TestNumber`・すべて OFF で作ります。旧版の `$CallTimes` があれば、その時刻の行を ON にして有効にします(移行用)。

### 発信試験の成否と受信レベル

- 1 回の試験は「発信直前の `AT+CSQ` → `ATD<番号>;`(通話中も `AT+CSQ`)→ `ATH` → 切断直後の `AT+CSQ`」です。
- 送信中に端末が干渉を受けていないかを見るのが目的なので、通話中の rssi・BER を直前・直後と比べられるようにしています。画面の「差」(通話中の平均 − 直前)が大きなマイナスなら、送信中に受信が下がっています。
- **IsatPhone 2 は、失敗しても `ATD` に `OK` を返し、`NO CARRIER` も出しません。** 代わりに、発信中に独自の通知(`+SKCPI`・`+SKCCSI`・`+SKGPSPOSI`・`+CIEV`)を自分から送ってきます。`AtIo.exe` は待っている間に受け取った文字をすべて出力するので、これらは新しいコマンドを送らなくても応答に入っています。
- 判定は、区切り行で分けた「`ATH` より前」の部分で行います。順に、COM のエラー → `ATD` の最初の応答が `OK` でない → `ATH` より前の切断の通知(`+SKCCSI` 状態 6 / `+SKCPI` 段階 1)→ `ATH` より前の `NO CARRIER` など → 独自通知はあるのに回線割当(段階 4)まで進まない、のどれかなら失敗です。ただし、経過通知(呼出音)まで進んだあと理由 16・18・19 で切れたものは、呼は成立していたので成功とします。
- `ATH` のあとに来る切断の通知(理由 16 など)は、こちらが切ったものなので判定に使いません。
- 独自通知を出さない機器では、これまでどおり `ATD` の応答(`OK` なら成功)で判定します。
- 切断の通知より後に送った通話中の `AT+CSQ` は、通話中の値に数えません(切れたあとは送信していないため)。
- 通話中の `AT+CSQ` が `ERROR` を返しても、発信の成否には影響しません。
- 通知の意味は公開資料がなく、実機の記録からの推定です([at-command-table.md](at-command-table.md) の「IsatPhone 2 の独自通知」)。
- 送信レベルは AT コマンドでは取れないので、記録するのは受信レベル(rssi)と BER です。
- 通話中の値の平均・最小(rssi)、最大(BER)は、`99`(不明)を除いて計算します。
- 同じ分に 2 度は発信しません。発信の直後には、いつもの取得(`AT+CSQ`・`AT+CREG?`)を 1 回行います。

### 受信グラフは横スクロールで過去を見る

- 受信グラフ(監視用)には `$HistoryHours`(既定 72 時間 = 3 日)分の点を持ちます。点の数は「時間 × 3600 ÷ 取得周期 + 1」(3 分周期・3 日なら 1441 点、上限 3000 点)。旧版の `$HistoryMax` は使いません。
- 起動時は、先月と今月の CSV から `$HistoryHours` 時間以内の行を読んで復元します(月をまたいでも途切れません)。
- 画面では、グラフの横幅を「点の数 × 6px」(3 日で約 8,600px)にして横スクロールで見せます。Chart.js の時間軸(日付ライブラリが必要)は使わず、横軸は取得した順に並べ、ラベルを「時刻」と「月/日」の 2 段にしています。Monitor が止まっていた時間は詰めて描かれるので、ラベルの日時で確かめてください。
- 縦軸の目盛りがスクロールで見えなくならないよう、描画のたびにグラフの左端(縦軸の目盛りの部分)を別の canvas に写し、左に重ねて固定しています。
- 更新のたびに右端に合わせるのは、右端(最新)を見ているときだけです。過去を見ている途中は位置を動かしません。

### 監視と評価を分ける (評価トレンド)

- 監視は 3 分ごとの全点を 3 日分。評価は 1 週間単位なので、全点を描くと点が多すぎて重く、canvas の幅の上限にも近づきます。そこで評価用には、Monitor が `$TrendDays`(既定 7 日)分の受信ログを **15 分ごとにまとめた** `trend.js` を別に作ります(平均・最小・最大・BER の最大・取得失敗の数・圏外の数)。1 週間で 673 区間ほどなので、画面幅に収まり、軽く動きます。
- `trend.js` には、同じ期間の発信試験の結果と変化のコメントも入れます。作り直すのは 10 分ごと・発信試験のあと・コメントを取り込んだあとです。`data.js` は軽いまま(3 秒ごとの読み直し)、`trend.js` は画面が 1 分ごとに読み直します。
- まとめた区間は、データがなくても時間どおりに並べます。Monitor が止まっていた時間は空白になるので、止まっていたことが見てわかります(受信グラフは取った順に並べるので、止まっていた時間は詰めて描かれます)。
- 月をまたぐ期間は、該当する月の CSV をすべて読みます。

### 変化のコメント

- `logs\events.csv`(UTF-8 BOM 付き)に `Timestamp,Text,Id` の形で残します。Id は画面から足したときの保存日時で、画面が「反映済み」を確かめるのに使います。メモ帳で足した行は Id が空でもかまいません。
- 画面の「コメントを追加」は、タイムテーブルと同じく `csqwatch_event.json` をダウンロードとして保存し、Monitor が 5 秒ごとに受け取り先を探して取り込みます。内容の改行は空白に、`,` は `、` に置き換え、200 文字までにします。取り込んだファイルは `logs\calltable_history\` へ移します。
- コメントは評価トレンドと受信グラフの両方に縦線で描きます(Chart.js のプラグインで、グラフを描いたあとに線とラベルを重ねる)。受信グラフでは、コメントの時刻以前でいちばん近い点の位置に引きます。

### 更新停止の検知

`data.js` に取得周期(`intervalSec`)を含め、画面側で最終更新時刻と比べます。周期の 2 倍 + 10 秒を超えると **STALE** 表示にします。
`Monitor` の停止、COM の切断、`data.js` が出力されないとき、のいずれにも気づけます。

### 試験ログ

不具合の解析とデータ取得の検証のため、`logs\test_YYYYMMDD.log` に 1 行ずつ記録します。書式と見かたは README の「試験ログ」を参照してください。

- 1 行ごとにファイルを開いて追記し、閉じます。強制終了や PC の再起動の直前まで残ります。
- 応答はログ用に整形します(PowerShell 5.1 が外部プログラムのエラー出力に付ける「発生場所 …」などの飾りを除く)。判定には整形前の応答を使います。
- メインループを `try { } finally { }` で囲み、Ctrl+C で止めたときに `STOP` を残します。× ボタンで閉じた・再起動・強制終了では残らないので、「`STOP` がない = 外部要因」と見分けられます。
- 予期しないエラーは `trap` で `ERR UNHANDLED`(行番号付き)を残してから止まります。

## data.js の形式

```js
window.CSQ_DATA = {
  "mock": false,
  "intervalSec": 180,
  "rssiMax": 55,                     // Config.ps1 の $RssiMax (グラフの縦軸の最大値)
  "deviceName": "IsatPhone 2",       // Config.ps1 の $DeviceName (画面の見出し)
  "call": {                          // 発信試験
    "enabled": true, "durationSec": 20, "duringEverySec": 5,
    "savedAt": "2026-10-26 09:00:00",          // 取り込み済みのタイムテーブルを画面で保存した日時
    "slots": [ { "hour": 0, "time": "00:01", "number": "+81...", "on": true } ],   // 24 行
    "appliedAt": "...", "source": "csqwatch_calltable.json",    // 取り込んだ日時とファイル名
    "error": "", "errorAt": "", "rejectedSavedAt": "",          // 取り込めなかったときの理由
    "inbox": "C:\\Users\\...\\Downloads",                       // 受け取り先
    "today": [ { "t": "...", "slot": 9, "time": "09:01", "number": "+81...", "result": "成功", "code": "OK",
                 "rb": "37", "bb": "0", "rdAvg": "26.7", "rdMin": "25", "bdMax": "3", "n": "3", "ra": "37", "ba": "0", "dur": "20" } ],
    "todayTotal": 14, "todayOk": 12
  },
  "current": {
    "LastUpdate": "2026-10-04 08:00:03",
    "CsqOk": true,                   // false = 端末から値を取れなかった (画面は「取得失敗」)
    "Rssi": 37,                      // AT+CSQ の <rssi> (IsatPhone 2 は 0-55, 99=圏外)
    "Dbm": "37 / 55",                // 画面の Signal Level。生の値 / $RssiMax (GSM の dBm 換算は使わない)。失敗時は "取得失敗"
    "Ber": 0,
    "RegStatus": "同期完了 (Registered)",
    "Extras": [ { "name": "Operator", "value": "..." } ]   // Config.ps1 の $Extras
  },
  "history": [ { "t": "2026-10-04 08:00:03", "r": 37 } ]   // 直近 $HistoryHours 時間分。端末の圏外(99)は 0、取得失敗は null (グラフが途切れる)
};
```

`Dbm` という名前は、以前 dBm を入れていたときの名残です(画面との互換のため名前は変えていません)。

## CSV の形式

`logs/csq_YYYYMM.csv`(UTF-8 BOM 付き、Excel でそのまま開けます)

```
Timestamp,RSSI,Level,BER,RegStatus,Notes
2026-10-04 08:00:03,37,37 / 55,0,同期完了 (Registered),Periodic
2026-10-04 08:03:03,99,取得失敗,99,ポートエラー,IO Error: 書き込み操作がタイムアウトしました。
2026-10-04 08:01:00,,,,,TestCall +81... 成功   ← 発信試験をした印 (結果の詳細は call_YYYYMM.csv)
```

- 取得に失敗した行は、3 列目が `取得失敗`(2026-10-21 より前は `N/A`)、2 列目が `99` です。端末が返した圏外(`99`)とは 3 列目で見分けます。
- 3 列目は 2026-10 までは `dBm`(GSM の換算値)でした。Inmarsat の rssi には使えないため、`Level`(生の値 / 最大値)に変えています。古い CSV の `dBm` 列の値は意味を持たないので、分析には 2 列目の `RSSI` を使ってください。
- `Notes` には、`Periodic`、`CSQ no response`、COM エラーのメッセージ(1 行目)などが入ります。
- 旧名(IsatMon)のころの CSV は `isat_YYYYMM.csv` です。新しい CSV がまだない月は、起動時に旧 CSV からグラフを復元します(読むだけで、書き換えません)。

## 発信試験の CSV

`logs/call_YYYYMM.csv`(UTF-8 BOM 付き)。1 回の発信試験で 1 行です。

```
Timestamp,Slot,Time,Number,Result,Code,RssiBefore,BerBefore,RssiDuringAvg,RssiDuringMin,BerDuringMax,DuringSamples,RssiAfter,BerAfter,DurationSec,Stage,Cause,CauseText,GpsPos,CievMin
2026-10-28 07:11:00,7,07:11,+819012345678,成功,OK / 到達: 経過通知,37,0,31.3,29,5,3,38,0,20,経過通知,,,1,4
2026-10-28 08:01:00,8,08:01,+819012345678,失敗,切断 理由31 (正常、その他) / 到達: 発信,37,0,,,,0,37,0,20,発信,31,正常、その他,0→1,3
2026-10-28 10:01:00,10,10:01,+819012345678,失敗,BUSY,38,0,,,,0,38,0,20,,,,,
```

| 列 | 内容 |
|---|---|
| `Slot` / `Time` | タイムテーブルの行(時)と、その行の時刻 |
| `Result` / `Code` | `成功` / `失敗` と、判定のもとになった応答 |
| `RssiBefore` / `BerBefore` | 発信直前の `AT+CSQ` |
| `RssiDuringAvg` / `RssiDuringMin` / `BerDuringMax` | 通話中の `AT+CSQ` の rssi の平均・最小と、ber の最大(`99` は除く) |
| `DuringSamples` | 通話中に値が取れた回数 |
| `RssiAfter` / `BerAfter` | 切断直後の `AT+CSQ` |
| `DurationSec` | 呼出秒数 |
| `Stage` | 到達段階(発信 / 回線割当 / 呼の処理中 / 経過通知 / 相手を呼出 / 応答) |
| `Cause` / `CauseText` | `ATH` より前に網から切断されたときの理由番号(ITU-T Q.850)と意味 |
| `GpsPos` | 発信中の `+SKGPSPOSI` の値の変化(例 `0→1`) |
| `CievMin` | 発信中の `+CIEV: 2`(アンテナ表示)の最小 |

`Stage` 以降の 5 列は 2026-10-28 に足しました。それより前の行は空欄です。古い見出しのファイルに書き足すときは、見出しの行だけを新しいものに置き換えます。

値が取れなかった欄は空欄です。起動時には、今日の分を読み戻して画面の「今日の結果」に出します。

## 文字コードの規約

`.ps1` `.cs` `probe_commands.txt` は **UTF-8(BOM 付き)・CRLF** です(`.editorconfig` と `.gitattributes` で固定)。
BOM がないファイルは、日本語環境の Windows PowerShell 5.1 と `csc.exe` が ANSI(cp932)と誤読し、日本語の文字列が壊れます。
`.bat` は cmd が cp932 を使うため、**ASCII のみ**にしています(日本語を入れないでください)。
`.md` は UTF-8(BOM なし)・LF です。説明書 `app/manual.html` は MD から `tools\build_manual.bat`(`Build-Manual.ps1`、PowerShell 5.1 のみ)で生成します(直接編集しない)。

## 補足

- `Common.ps1` の `Invoke-At` は PowerShell から `AtIo.exe` を呼びます。コマンド文字列に `"` を含むもの(`AT+CGDCONT=1,"IP","apn"` など)は、PowerShell 5.1 のネイティブコマンド引数の扱いで壊れるため、現状は送れません。
- `-Mock` の疑似応答は `Common.ps1` の `Get-MockResponse` にあります。`$Extras` で新しいコマンドを試すときは、ここに疑似応答を足すと画面で確認できます。疑似データは IsatPhone 2 の実測に近い範囲(rssi 20〜50)で動きます。
- 実行環境は Windows 11 標準の PowerShell 5.1・.NET Framework 4.x・Edge だけです。インストールも管理者権限も要りません。
