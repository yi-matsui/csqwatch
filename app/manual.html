CsqWatch

Author: yuichi(Yuichi Matsui, JH0VEQ)

AT コマンドで話せる通信機器の受信状態(AT+CSQ)を監視する小さなツールです。

Windows 11 に最初から入っているものだけで動き、インターネットにつながらない環境で使います。

使っているのは 3GPP TS 27.007 の標準 AT コマンド(AT+CSQ・AT+CREG?・ATD/ATH)だけなので、衛星電話・携帯電話モジュールなど、AT コマンドで話せる機器ならおおむね動きます。機器ごとの違い(信号の目盛りの最大値など)は設定で合わせます。

動作確認済みの機器: Inmarsat IsatPhone 2(2026-10-14、実機で確認)。機器ごとの注意は「機器ごとの注意」を参照してください。

C# で書いているのは「AT コマンドを 1 つ送って応答を返す」AtIo.exe だけです。 どのコマンドを送り、結果をどう解釈し、どう表示するかは、PowerShell・設定ファイル・HTML 側にあります。 C# を書ける人がいなくても保守できる構成です。

評価版のイメージ

  • まずは基本動作を確認するための最小機能を目指す。

最終機能のイメージ

特長

  • Web サーバ不要 — index.html をダブルクリックで開くだけ。収集側が data.js を書き出し、画面がそれを読みます
  • AT コマンドは外出し — 追加したい項目は設定ファイルに 1 行足すだけ
  • 実機なしで試せる — 疑似データの -Mock モード
  • 対応コマンドの調査ツール — Probe.bat が機器の対応状況を一覧にします
  • 止まったことに気づける — 更新が止まると、画面右上が STALE(赤)になります
  • 完全オフライン — Chart.js を同梱しています
  • 社外監視の窓を邪魔しない — 画面は社外監視 (VPN) とは別のブラウザ・別のプロセスで開き、Monitor 自身も CPU 優先度「通常以下」で動きます
  • 入口は Monitor.bat ひとつ — 監視が止まっていれば始め、動いていれば監視画面を前面に出すだけ。何度押しても、監視が二重に動くことも、画面の窓が増えることもありません
  • 試験ログ — 送ったコマンド・生の応答・所要時間・解析結果などを 1 行ずつ記録し、不具合解析とデータ取得の検証に使えます
  • 監視と評価を分けて見る — 監視は 3 分ごとの全点を 3 日分(横スクロール)、評価は 15 分ごとにまとめた 1 週間のトレンドで見ます。変化(同軸を抜いた・衛星出力 UP など)のコメントを、どちらのグラフにも縦線で表示します
  • 発信試験 — 24 個のタイムテーブル(各時 1 行)で定時に発信し、成功・失敗と、発信直前・通話中・切断直後の受信レベル(rssi)と BER を記録します。タイムテーブルは監視画面で編集できます

仕組み

[AT コマンド機器] ──COM── AtIo.exe ◀── Monitor.ps1 ──┬─▶ data.js        ◀── index.html (別ブラウザの専用窓)
                          (I/O だけ)   (収集ループ)    ├─▶ logs/csq_YYYYMM.csv     (取得結果)
                                                       ├─▶ logs/call_YYYYMM.csv    (発信試験の結果)
                                                       └─▶ logs/test_YYYYMMDD.log   (試験ログ)

index.html (発信試験の「保存」) ──▶ ダウンロードフォルダ\csqwatch_calltable.json ──▶ Monitor.ps1 が取り込み ──▶ CallTable.json

AtIo.exe は AT コマンド 1 回ごとに起動し、COM ポートを「開く → 送受信 → 閉じる」で終わります。COM ポートを開きっぱなしにはしません。

設計の詳細は docs/architecture.md、関数ごとの役割は docs/functions.md、AT コマンドの対応範囲と調べ方は docs/at-commands.md を参照してください。

動作環境

Windows 11(Windows PowerShell 5.1 と .NET Framework 4.x が標準で入っています)。追加のインストールは不要です。

運用する人へ(これだけ覚えてください)

  • 監視画面が見当たらない・閉じてしまった → Monitor.bat をダブルクリック
    • 監視が動いていれば、画面が前面に出る(閉じていれば開く)だけです。黒い窓は 5 秒で自動的に閉じます。
    • 監視が止まっていれば、監視を始めて画面を開きます。
  • 画面右上が STALE(赤)のときは、監視が止まっています。同じく Monitor.bat を押します。
  • 「CsqWatch 稼働中 (閉じないでください)」という黒い窓は閉じないでください。
  • 社外監視(VPN)の窓が最優先です。監視画面はそれとは別のブラウザで開きます。
  • 説明書は、監視画面の右上の 「説明書」 から開けます(app\manual.html をダブルクリックしても開けます)。
  • 発信試験のタイムテーブルは、監視画面の下の 「タイムテーブルを編集」 で変えます。「保存」のあと「反映済み」と出れば完了です(詳しくは「発信試験」)。

クイックスタート

app/ フォルダの中で作業します。

  1. build.bat — AtIo.exe を作ります(Windows 標準の csc.exe を使用)
    • できたら AtIo.exe -HELP を実行すると、使い方と引数の説明が表示されます
  2. MonitorMock.bat — 疑似データでダッシュボードが動くことを確認します(画面は別ブラウザの専用窓で開きます)
  3. 実機につなぐ
    1. Monitor.bat を一度起動すると、Config.ps1 が自動で作られます。止めて、$Port を実際の COM 番号に直します
    2. Probe.bat — 機器が対応している AT コマンドを調べます
    3. Monitor.bat — 実機の値で動きます

社内ネットワークなど外部につながらない PC へは、app/ フォルダごとコピーすれば動きます。 USB メモリを使えない場合は、Git(または GitHub の ZIP)経由で導入します。手順は docs/deploy-via-git.md を参照してください。

バッチファイルの使い方

app/ フォルダの 5 つの .bat は、どれもダブルクリックで動きます。コマンドプロンプトから実行してもかまいません(どこから実行しても、自分のフォルダに移動してから動きます)。 実行が終わると pause で止まり、「続行するには何かキーを押してください」と出るので、結果を読んでから閉じられます(Monitor.bat を、監視が動いているときに押した場合だけは止まらずに閉じます)。

バッチ役割引数できるもの
build.batAtIo.cs から AtIo.exe を作るなしAtIo.exe
MonitorMock.bat疑似データで画面を確認する(実機不要)なし監視画面が開き、グラフが動く
Monitor.bat実機を監視する。動いていれば監視画面を前面に出す-Mock、-IntervalSec <秒>logs\csq_YYYYMM.csv、logs\test_YYYYMMDD.log、data.js
Probe.bat機器が対応している AT コマンドを調べる-Mock、-ListFile <ファイル名>probe_日時.txt
Merge.bat過去のデータを、今のデータの保存先にまとめる(Monitor を止めてから)まとめたいフォルダ(省略するとフォルダを選ぶ画面)保存先の CSV・events.csv・試験ログ、merge_report_日時.txt

build.bat

  • Windows に入っている csc.exe(.NET Framework 4.x)で AtIo.exe を作ります。64bit 版が見つからなければ 32bit 版を使います。
  • 成功すると BUILD OK: AtIo.exe、失敗すると BUILD FAILED と表示され、その上にコンパイラのエラーが出ます。
  • AtIo.cs を直したときも、これを実行し直します。

MonitorMock.bat

  • 疑似データを 3 秒ごとに作り、監視画面を開きます。画面右上は LIVE (MOCK) になります。
  • COM ポートには触りません。最初の動作確認や、画面(index.html)をいじるときに使います。

Monitor.bat

  • 実機の値を、Config.ps1 の周期(既定 180 秒)で取得します。監視画面も自動で開きます(開き方は「監視画面とブラウザ」を参照)。
  • コンソールの窓のタイトルは「CsqWatch 稼働中 (閉じないでください)」になります。
  • すでに動いているときに起動すると、2 つ目は監視を始めずに、監視画面を前面に出し(閉じていれば開き)、5 秒後に自動で閉じます。別のユーザーでログオンして起動した場合も監視は二重に動きません。
  • 初回は Config.ps1 が自動で作られます。$Port を実際の COM 番号に直してから使ってください。

  • 引数は、コマンドプロンプトから付けて実行します(ダブルクリックでは渡せません)。

    Monitor.bat                      実機を監視 (周期は Config.ps1 の $PollSec)
Monitor.bat -Mock                疑似データ
Monitor.bat -IntervalSec 10      周期を 10 秒にする (動作確認用)

    ダブルクリックで引数付きにしたいときは、Monitor.bat のショートカットを作り、「リンク先」の末尾に -IntervalSec 10 のように足します。

Probe.bat

  • probe_commands.txt のコマンドを順に送り、結果を probe_日時.txt に保存します。Monitor.bat は先に止めておきます。
  • Probe.bat -ListFile 別のファイル.txt で、別のコマンド一覧を使えます。Probe.bat -Mock は、実機なしの試し実行です。

Merge.bat(過去のデータをまとめる)

別の PC や前のフォルダで取ったデータを、今のデータの保存先(Config.ps1 の $LogDir)に足します。評価トレンドや受信グラフで、まとめて見られるようになります。

  1. Monitor を止めます(動いていると「Monitor が動いています」と出て止まります)。
  2. Merge.bat をダブルクリックし、過去のデータのフォルダ(logs など。中のフォルダも探します)を選びます。複数あるときは Merge.bat "D:\old\logs" "E:\pc2\app\logs" のように並べます。
  3. ファイルごとに「今まで・増える・重複・同じ日時で中身が違う」の件数が出ます。Y を押すと確定します(それまでは何も書き換えません)。
  4. Monitor を起動すると、まとめたデータでグラフと評価トレンドを作り直します。
  • まとめるもの:受信ログ csq_YYYYMM.csv(旧名 isat_YYYYMM.csv も)、発信試験 call_YYYYMM.csv、変化のコメント events.csv、試験ログ test_YYYYMMDD.log。
  • 同じ行は 1 つにし、日時の順に並べ直します。各行は、ファイル名ではなく行の日時の月のファイルに入れます。列の少ない旧版の発信試験の行は、空の列を足して今の形にそろえます。
  • 同じ日時で中身が違う行は両方残し、件数を出します。別の端末・別の PC のデータを混ぜていないかの目安にしてください。
  • コメントは、日時と内容が同じなら同じものとして 1 つにします(2026/10/28 9:30 のような書き方もそろえます)。
  • 試験ログは、保存先に同じ名前がなければそのままコピーし、中身が違えば test_YYYYMMDD_merged1.log として足します。
  • 書き換える前のファイルは <保存先>\merge_backup\日時\ に、結果は <保存先>\merge_report_日時.txt に残します。元のフォルダは変更しません。
  • 15 分ごとにまとめた評価トレンドで長い期間を見るときは、Config.ps1 の $TrendDays を増やし(31 日まで)、画面の 「全期間」 を押します。

止めかた

  • Monitor.bat と MonitorMock.bat は止めるまで動き続けます。Ctrl+C を押すか、ウィンドウを閉じます。「バッチ ジョブを終了しますか」と聞かれたら Y を入力します。
  • 止めたあとも、監視画面は開いたままです。更新が止まると、右上が STALE(赤)になります。
  • 次に起動すると、同じ月の CSV から直近のグラフを復元して再開します。

画面の見かた

表示意味
Downlink RSSI に数値、Signal Level に 38 / 55端末が値を返した(/ の右は目盛りの最大値 $RssiMax。IsatPhone 2 は 55)
Downlink RSSI に 圏外 (99)端末自身が「圏外・測定できない」と返した。グラフは 0 で描く
Downlink RSSI に --、Signal Level に赤の 取得失敗端末から値を取れなかった(COM ポートのエラー・無応答など)。端末の圏外ではない。グラフは線が途切れる
右上 STALE(赤)監視(Monitor)が止まっている

受信レベルのグラフ(監視用)は、過去 3 日分(Config.ps1 の $HistoryHours、既定 72 時間)の 3 分ごとの全点を横に長く描きます。横スクロールで過去を見られます。

  • 横軸のラベルは「時刻」と「月/日」の 2 段です。点にマウスを当てると、日付つきの時刻が出ます。
  • 縦軸の目盛りは、スクロールしても左に残ります。
  • ふだんは右端(最新)を表示し、更新のたびに右端に合わせます。過去を見ている間は位置を動かさず、「最新へ ▶」 で右端に戻ります。
  • グラフの上に、表示している期間と点の数が出ます。
  • 変化のコメントがあれば、その時刻に黄色の縦線とラベルを出します。

評価トレンド

1 週間単位の評価のために、受信ログと発信試験の結果を 15 分ごとにまとめて 1 つのグラフに描きます(画面の一番下)。

  • 期間は 1 日 / 3 日 / 1 週間(既定)から選びます。表示できる日数は Config.ps1 の $TrendDays(既定 7 日)です。
  • 青の線は 15 分ごとの CSQ の平均、薄い帯は最小〜最大、橙の階段線は BER の最大(右の目盛り)です。
  • 発信試験の結果を、成功は緑の点、失敗は赤の × で重ねます。点に触れると、時刻・結果・切断理由・到達段階・GPS が出ます。
  • 何も描かれていない時間は、Monitor が止まっていたか、すべて取得失敗だった時間です。
  • グラフの下に、期間の要約(CSQ の平均・最小・最大、BER が 0 より大きい区間の数、取得失敗の回数、発信試験の成功率)と、時間帯別の発信試験の成功(0〜23 時。緑 90% 以上 / 黄 50% 以上 / 赤 50% 未満)を出します。時間帯で成功率が変わるかどうかは、地上の携帯電話などの干渉を疑うときの手がかりになります。
  • trend.js は Monitor が 10 分ごと(と、発信試験・コメントの追加のあと)に作り直します。画面は 1 分ごとに読み直します。

変化のコメント

同軸の抜き差し、減衰器の変更、衛星側の対応、ファームの更新など、結果に影響しそうな変化を日時つきで書き込みます。評価トレンドと受信グラフに黄色の縦線で表示され、グラフの下に一覧が出ます。

  1. 評価トレンドの 「コメントを追加」 を押します。
  2. 日時と内容を入れて 「保存」 を押します。日時の欄は空で開きます(入れ忘れて今日の日付で登録されないように)。今の時刻にするときは 「今」 を押します。2026-10-28 09:30 のほか、2026/10/28 9:30 や全角数字でも受け付けます。
  3. csqwatch_event.json がダウンロードフォルダに保存され、Monitor が取り込んで logs\events.csv に書きます。取り込まれると「反映済み」と出ます。

直す・消す:グラフの下のコメントの一覧で、直したい行を押すと入力欄が開きます。日時・内容を直して「保存」、または「削除」を押します。

  • ダウンロードフォルダの csqwatch_event.json を直しても反映されません(Monitor が 5 秒以内に取り込んで logs\calltable_history\ へ移すため)。画面の一覧から直してください。
  • logs\events.csv をメモ帳で直接直してもかまいません(日時,内容,Id の形。Id は空でよい)。保存すると数秒で画面に反映されます。Excel で直すと日時が 2026/10/28 9:30 の形になりますが、そのまま読めます。Excel で開いたままにはしないでください。

発信試験の欄の見かたは「発信試験」を参照してください。

発信試験

決まった時刻に試験の発信をして、成功・失敗と、そのときの受信レベル(rssi)・BER を記録します。 送信中に端末が干渉を受けていないかを確かめるため、発信直前・通話中(数秒ごと)・切断直後の 3 つの時点で AT+CSQ を測ります。通話中だけ rssi が下がる・BER が悪くなるなら送信に関係した干渉、3 つとも悪いなら設置環境、と切り分けられます。

タイムテーブル

  • 1 日 24 行(0 時〜23 時の各 1 行)です。初期値は、各時の 01 分・番号は Config.ps1 の $TestNumber・すべて OFF です。
  • 行ごとに「ON / OFF」「時刻(HH:MM、任意に変更可)」「着信番号」を決めます。
  • 全体として「発信試験を有効にする」と、次の 3 つがあります(画面の「タイムテーブルを編集」で変えられます)。
項目範囲意味
通話時間5〜900 秒発信(ATD)から切断(ATH)まで。相手が出るまでの呼出の時間も含みます
回数1〜10 回1 つの時刻で続けて発信する回数
間隔1〜60 分切断してから、次の発信まで
  • 例:衛星事業者の接続試験「3 分の通話を、切断してから 5 分あけて 3 回」は、通話時間 180 秒(呼出の分を足すなら 200 秒など)・回数 3・間隔 5 分です。21:01 の行なら、21:01 に発信 → 21:04 ごろ切断 → 21:09 ごろ 2 回目 → 21:12 ごろ切断 → 21:17 ごろ 3 回目、で 21:21 ごろに終わります(直前・直後の AT+CSQ の分、数秒ずつ後ろにずれます)。Config.sample.ps1 の初期値もこの値です。
  • 1 つの時刻の試験の長さのめやすは「回数 × (通話時間 + 30 秒) + (回数 − 1) × 間隔」です(上の例で約 21 分)。ON の時刻どうしがこれより近いと、保存できません。
  • 発信と発信のあいだも、ふだんの受信の取得(AT+CSQ)は続けます。
  • 試験の途中で「発信試験を有効にする」を外して保存すると、残りの回は取りやめます。スリープなどで予定より 2 分以上遅れた回は、間隔が崩れるので発信しません(試験ログに WARN)。
  • 有効にして、ON の行の時刻になったときだけ発信します。初期状態ではどこにも発信しません。

編集のしかた

  1. 監視画面の下の「発信試験」で 「タイムテーブルを編集」 を押します。
  2. ON・時刻・番号を変えます。「番号」欄に入れて「全行に入れる」で全行の番号をまとめて変えられます。「全て ON」「全て OFF」「時刻を各時 01 分に戻す」もあります。
  3. 「保存」 を押し、確認の画面で内容を確かめて OK を押します。
  4. csqwatch_calltable.json がダウンロードフォルダに保存され、Monitor が 5 秒ごとにそれを探して取り込みます。取り込まれると、欄の上に 「反映済み」 と出ます(取り込んだファイルは logs\calltable_history\ に移ります)。
  • 保存の前に、時刻の形式・時刻の重なり(ON の行どうし)・番号の形式を確かめます。Monitor でも同じ確認をし、おかしければ取り込まずに理由を画面に出します(タイムテーブルは前のまま)。
  • 「反映済み」が出ないときは、Monitor が動いているか、ファイルが受け取り先(既定はダウンロードフォルダ)にあるかを確かめてください。Monitor を別のユーザーで動かしているときは、両方が使えるフォルダを Config.ps1 の $CallTableInbox に指定し、ブラウザの保存先もそこにします。
  • 誤った番号への発信を防ぎたいときは、Config.ps1 の $CallNumberAllow に発信してよい番号を並べます(それ以外の番号は取り込みません)。

試験の流れと判定

  1. 発信直前に AT+CSQ
  2. ATD<番号>; で発信。OK を受けてから $CallDuringEverySec 秒(既定 5 秒)ごとに AT+CSQ を送る(通話中の測定)。通話時間が過ぎたら ATH で切る
  3. 切断直後に AT+CSQ

IsatPhone 2 は、失敗しても ATD に OK を返し、NO CARRIER も出しません(2026-10-28 に実機で確認)。そこで、通話中に端末が自分から送ってくる独自の通知(+SKCPI 呼の進み具合・+SKCCSI 通話の状態と切断理由・+SKGPSPOSI GPS の位置・+CIEV 表示器)を読んで判定します。

判定条件
失敗COM のエラー、ATD の応答が OK でない(ERROR・+CME ERROR・BUSY など)、応答なし
失敗(切断 理由 n)こちらの ATH より前に、網から切断された(+SKCCSI の状態 6、+SKCPI の段階 1)。理由番号(ITU-T Q.850)と意味を記録
失敗(呼出中に終了)ATH より前に NO CARRIER などが来た
失敗(回線未確立)独自通知はあるのに、回線割当まで進まなかった
成功(呼出後に切断)相手の呼出(呼出音)まで進んだあと、理由 16・18・19(通常の切断・応答なし)で切れた
成功上のどれにも当たらない

独自通知を出さない機器では、これまでどおり ATD の応答(OK なら成功)で判定します。通知の意味は公開資料がなく、実機の記録からの推定です(「AT コマンド表」の「IsatPhone 2 の独自通知」)。

実機で確かめたこと:相手の呼出音が鳴った回は、+SKCPI が段階 5・音=1(経過通知+呼出音)まで進みました(ALERT は出ません)。画面ではこれを「到達: 相手を呼出(呼出音)」と表示します。

実機で見つかった失敗の例:発信の途中で +SKGPSPOSI: 0(GPS の位置なし)になり、網から理由 31 で切断、切断後に +SKGPSPOSI: 1 に戻りました。GPS の同軸は別系統なので、GPS が 0 になるのは失敗の原因ではなく、失敗した回に現れる状態と考えています(意味は調査中)。比べられるように GPS の状態も記録しています。

通話中の AT+CSQ は、発信の応答(OK)を受け取ってから送ります。発信の途中で文字を送ると発信そのものが中断される機器があるためです。機器が通話中に AT コマンドを受け付けない場合は、通話中の値が「取得なし」になり、試験ログに WARN が出ます(直前・直後の値と成否はそのまま記録します)。

監視画面とブラウザ

この PC では、社外監視(VPN 経由の衛星事業者のダッシュボード)の窓が最優先です。監視画面はそれに影響を与えないように開きます。

  • 別のブラウザで開く — 既定($Browser = 'auto')では Chrome → Edge の順に探します。社外監視の窓と種類が違うので、閉じる窓を取り違えにくくなります。Firefox は他の業務で使うので auto には含めていません。
  • 別のプロセスで開く — 専用のプロファイル(app\profile_<ブラウザ名>)で起動するので、社外監視のブラウザとはプロセスが分かれます。こちらが重くなっても落ちても巻き込まず、Cookie やログイン情報も共有しません。
  • 窓を増やさない — 監視画面がすでに開いていれば、新しく開かずにその窓を前面に出します。専用プロファイルで動いているブラウザのプロセスを探して前面に出すので、社外監視の窓は動かしません。
  • タブのない専用の窓 — Chrome と Edge はアプリモードで開くので、社外監視のタブに混ざりません。Firefox は通常の窓(タブ付き)ですが、別プロセス・別窓です。
  • 優先度を下げる — Monitor は CPU 優先度「通常以下」で動き、監視画面のブラウザと AtIo.exe もそれを引き継ぎます。
  • ネットワークを使わない — Monitor と監視画面はローカルのファイルだけで動き、VPN の回線には何も流れません。
  • このツールは、ブラウザを閉じたり、他の窓を操作したりしません。

設定は Config.ps1 で変えます。

項目既定値意味

$DashboardSize'1280,860'窓の大きさ(幅,高さ)。Chrome・Edge のみ

機器ごとの注意

機器によって、AT コマンドの対応範囲や値の目盛りが違います。新しい機器では、まず Probe.bat で対応状況を調べ、AT+CSQ=? の応答で目盛りの最大値を確かめてから、Config.ps1 の $RssiMax と $DeviceName を合わせてください。

Inmarsat IsatPhone 2(確認済み)

  • AT+CSQ の rssi は 0〜55、ber は 0〜15 です(AT+CSQ=? の応答 (0-55,99),(0-15,99))。GSM の dBm 換算は使えません。$RssiMax = 55 にします。
  • AT+CBC は使用禁止です。送ると端末がしばらく無応答になり、後続のコマンドも返らなくなります。
  • AT+CGREG?・AT+CGATT? は未対応(+CME ERROR: 4)、AT+CLAC も使えません(+CME ERROR: 25)。
  • PC からの通信には、メーカーの USB ドライバーが必要です(ドライバーなしでは COM ポートが見えても通信できません)。

詳しくは docs/at-command-table.md を参照してください。

旧名(IsatMon)からの移行

このツールは、以前は IsatMon という名前でした。メーカーの製品名に近い名前を避け、AT コマンド機器全般に使える名前に改めました。旧版から入れ替えるときは、次の点に注意してください。

  • 旧版の監視を止めてから入れ替えてください(二重起動防止の名前が変わったので、旧版と新版は互いを検出できません)。
  • I/O 用の EXE は IsatIo.exe から AtIo.exe に変わりました。build.bat を実行し直してください。古い IsatIo.exe は削除してかまいません。
  • 手元の Config.ps1 はそのまま使えます($IsatIoExe の行は使われなくなり、AtIo.exe を使います)。画面の見出しに機器名を出したいときは $DeviceName = 'IsatPhone 2' を足します。
  • CSV の名前は isat_YYYYMM.csv から csq_YYYYMM.csv に変わりました。同じ月の旧 CSV があれば、起動時にそこからグラフを復元します(旧ファイルは書き換えず、そのまま残ります)。
  • 画面のデータ名(window.ISAT_DATA → window.CSQ_DATA)も変わったので、index.html と Monitor.ps1 は必ず両方入れ替えてください。

注意

  • COM ポートは 1 本につき 1 プログラムだけです。Monitor.bat と Probe.bat は同時に動かさないでください(Monitor.bat どうしの二重起動は自動で防ぎますが、Probe.bat は防ぎません)。
  • IsatPhone 2 では AT+CBC を送らないでください(端末が無応答になります)。$Extras や probe_commands.txt に入れないでください。
  • logs\csq_YYYYMM.csv を Excel で開いたままにすると、その間は追記できず警告が出ます。コピーしてから開いてください。
  • .bat は -ExecutionPolicy Bypass で起動します。組織のポリシーで PowerShell の実行が禁止されている場合は、管理者に相談してください。
  • .ps1 .cs probe_commands.txt は UTF-8(BOM 付き) で保存してください。BOM がないと、日本語環境の PowerShell 5.1 や csc.exe が ANSI(cp932)と誤読して文字化けします。
  • 発信試験は既定で無効です。衛星電話の発信は通話料がかかります。ON の行の数・回数・通話時間に気をつけてください(24 行すべて ON・3 回・180 秒なら、1 日 72 回・計 216 分の発信になります)。
  • 試験ログ・発信試験の CSV・CallTable.json にはダイヤルした番号が入ります。公開・共有するときは番号を伏せてください(いずれも Git の管理外です)。
  • 旧版の $CallTimes(定時発信の時刻)は、CallTable.json を初めて作るときにだけ使います(その時刻の行を ON にして有効にします)。以後は監視画面で編集します。
  • PC がスリープすると取得が止まります。電源設定でスリープを「なし」にしておいてください(試験ログに「周期遅れ」が出ます)。

設計判断

HTTP サーバを使わない

画面は file:// で開く静的な HTML です。データは JSON を fetch せず、<script> タグで data.js を読み込みます。 fetch は file:// では CORS 制約で失敗しますが、<script> の読み込みは制約を受けません。 HttpListener による常駐サーバ(ブロッキング、CORS、エンコードの問題)が丸ごと不要になります。 URL にクエリ(?t=…)を付けてキャッシュを避けています。Edge・Chrome・Firefox のどれでも同じように動きます。

C# は I/O だけ

AtIo.exe は AtIo.exe <Port> <BaudRate> <Cmd> [WaitSec] [AfterCmd] [DuringCmd] [DuringEverySec] で動き、応答を標準出力へそのまま出します。 コマンドの種類・応答の解釈・周期などの知識は持ちません。C# を書き換える必要が出るのは、シリアル通信そのものを変えるときだけにしています。

  • 接続は 8N1、DTR/RTS を ON にして開き、開いた直後に ATE0V1(エコー OFF・文字応答)を送ってから、その応答を捨てます。
  • AfterCmd なし:応答の終端行(OK / ERROR / NO CARRIER / +CME ERROR: n など)を受信した時点で終了。WaitSec は上限です。終端は、これまでに受信した全文に対して判定するので、応答が途中で分割されても取りこぼしません。
  • AfterCmd あり:WaitSec 秒間受信を続け、その後 AfterCmd を送ります。試験発信(ATD…; → 呼出 → ATH)用です。
  • DuringCmd あり(AfterCmd と一緒のときだけ):Cmd の終端行を受信したあと、DuringEverySec 秒(既定 5、最小 2)ごとに DuringCmd を送ります。発信試験の通話中の AT+CSQ 用です。
    • Cmd(ATD)の応答前には送りません。V.250 では、コマンドの実行中に文字を受け取ると実行を打ち切る機器があり、発信が中断されるためです。ATD に応答がなければ、通話中のコマンドは一度も送りません。
    • 待ち時間の残りが 2 秒未満なら送りません(AfterCmd の直前に応答が重ならないように)。
    • NO CARRIER / BUSY / NO ANSWER / NO DIALTONE を受信したら、待ちを打ち切って AfterCmd に進みます。
    • 区切りとして、送る前に --- during <コマンド>、AfterCmd の前に --- after <コマンド> の行を標準出力へ出します。PowerShell 側はこれで「ATD の応答」「通話中」「切断」を分けます。DuringCmd を使わないときは区切りを出さないので、従来の出力と変わりません。
  • 終了コード:0 正常、1 引数不足、2 I/O エラー(エラー内容は標準エラー出力に IO Error: … で出す)。

COM ポートは開きっぱなしにしない

AtIo.exe は AT コマンド 1 回ごとに起動し、COM ポートを「開く → 送受信 → 閉じる」で終わります(1 回の取得で AT+CSQ と AT+CREG? の 2 回)。 周期の合間はポートが空くので、プロセスがポートを握り続けることがありません。 試験発信だけは、ATD から ATH までを 1 回の起動の中で行い、通話中はポートを開いたままにします。

取得のリトライはしない

AtIo.exe が失敗しても、その周期では再送しません。失敗として CSV と試験ログに記録し、次の周期(既定 180 秒後)に取り直します。 リトライを入れると失敗が見えにくくなるため、まず試験ログで失敗の頻度と傾向を確かめる方針にしています(警報のための「連続失敗回数」の考え方は今後の課題)。

収集ループは 1 秒刻み

取得周期(既定 180 秒)の間も、1 秒ごとに時刻を確認します。定時発信の HH:mm を取りこぼしません。 同じ分に 2 度発信しないよう、yyyyMMdd_HHmm をキーにして制御しています。発信の直後には、すぐに 1 回取得します。 次の取得は「前回の取得が終わってから $PollSec 秒後」です。取得にかかる時間の分だけ、時刻は少しずつ後ろにずれます。

入口は Monitor.bat ひとつ(二重起動の防止)

輪番で運用する人が覚えることを減らすため、入口を Monitor.bat ひとつにしています。

  • 起動時に名前付き Mutex(Global\CsqWatch。-Mock は Global\CsqWatch_Mock)を取ります。Global 名前空間なので、別のユーザーでログオンして起動した場合も検出できます。
  • 取れなかったとき(すでに動いているとき)は、監視を始めずに監視画面を前面に出し(閉じていれば開き)、5 秒後に終了コード 3 で終わります。Monitor.bat は終了コード 3 のときだけ pause せずに閉じます。
  • 前回の Monitor が異常終了していた場合は、Mutex の放棄(AbandonedMutexException)を受け取って普通に起動し、試験ログに WARN を残します。
  • 動いている Monitor の情報(PID・開始時刻・ユーザー・PC 名)は logs\monitor_running.txt に書き、Ctrl+C で止めたときに消します。

社外監視の窓を最優先にする

この PC では、社外監視(VPN 経由の衛星事業者のダッシュボード)の窓が最優先です。監視画面はそれに影響を与えないように開きます(Browser.ps1)。

  • 社外監視とは別のブラウザを選びます($Browser = 'auto' は Chrome → Edge の順。Firefox は他業務で使うので auto に含めない)。
  • 専用プロファイル(app\profile_<ブラウザ名>)で起動するので、社外監視のブラウザとはプロセスが分かれます。こちらが重くなっても落ちても巻き込まず、Cookie やログイン情報も共有しません。
  • Chrome・Edge はアプリモード(--app)で開き、タブのない専用の窓にします。
  • すでに開いていれば、専用プロファイルで動いているブラウザの本体プロセスを探し、そのプロセス ID を指定して前面に出します(WScript.Shell の AppActivate)。窓のタイトルで探さないので、社外監視の窓を動かすことはありません。
  • Monitor は CPU 優先度「通常以下」(BelowNormal)で動き、子プロセス(AtIo.exe・監視画面のブラウザ)もそれを引き継ぎます。
  • Monitor と監視画面はローカルのファイルだけで動き、ネットワークを使いません。

信号の目盛りは機器ごとに設定する

AT+CSQ の rssi の範囲は機器によって違います(GSM は 0〜31、IsatPhone 2 は 0〜55)。GSM の dBm 換算(-113 + 2 × rssi)は GSM 以外では意味を持たないので使わず、生の値を 値 / 最大値 で表示します。最大値は Config.ps1 の $RssiMax で、グラフの縦軸もこれに合わせます。

発信試験はタイムテーブルで動かし、画面で編集する

  • タイムテーブルは 24 行(各時 1 行)。行ごとに時刻・番号・ON/OFF、全体に「有効」・通話時間・回数・間隔を持ち、app\CallTable.json に保存します(version 2。回数・間隔のない旧版のものは Config.ps1 の $CallRepeat・$CallRepeatIntervalMin を使う)。
  • 画面は file:// の静的な HTML なので、ファイルを直接書けません。 そこで画面の「保存」は csqwatch_calltable.json をダウンロードとして保存し、Monitor が 5 秒ごとに受け取り先(既定はログオン中のユーザーのダウンロードフォルダ。$CallTableInbox で変更可。app\ も見る)を探して取り込みます。Web サーバを置かない方針を保ったまま、人の手でファイルを移す手順をなくしています。
  • ブラウザはダウンロードの途中は .crdownload / .part などの別名で書くので、書きかけのファイルを取り込むことはありません。同じ名前が続くと csqwatch_calltable (1).json のようになるので、csqwatch_calltable*.json の中で最も新しいものを取り込み、ほかは古いものとして扱います。
  • 取り込む前に、24 行あるか・時刻の形式・ON の行どうしの時刻の重なり・番号の形式(+ と数字 3〜20 桁。空白とハイフンは除く)・通話時間(5〜900 秒)・回数(1〜10)・間隔(1〜60 分。切断してから次の発信まで)・ON の時刻どうしが 1 つの試験の長さ(回数 × (通話時間 + 30 秒) + (回数 − 1) × 間隔)より離れているか・発信してよい番号($CallNumberAllow)を確かめます。1 つでもおかしければ全体を取り込まず、前のタイムテーブルのまま理由を画面と試験ログに出します。画面側でも保存の前に同じ確認をします。
  • 取り込んだファイルは logs\calltable_history\日時_ファイル名 へ移します(取り込めなかったものは末尾に .rejected、古いものは .old)。いつ・どう変えたかの記録になります。
  • 画面は、保存したタイムテーブルの savedAt と、data.js の call.savedAt(取り込み済み)・call.rejectedSavedAt(取り込めなかった)を比べて、「反映済み」かどうかを出します。
  • CallTable.json が壊れていて読めないときは、上書きせずに残し、発信試験を止めた状態で動きます。
  • 連続発信:ON の行の時刻になると、Monitor は「実行中の試験」($script:CallSeq。行・回数・済んだ回数・開始時刻・次の時刻)を作ります。メインループは毎秒これを見て、次の時刻になったら 1 回発信し、次の時刻を「その回の切断(直後の AT+CSQ まで終わった時刻)+ 間隔」にします(衛星事業者の指定が「切断してから 5 分あける」のため)。発信と発信のあいだは、ふだんの取得を続けます。1 回の発信(Invoke-TestCall)のあいだは、これまでどおりメインループは止まります。
  • 試験の途中で別の ON の時刻が来たら、その試験は見送ります(画面と Monitor の確認で重ならないようにしてあるので、通常は起きません)。発信試験が無効にされたら残りを取りやめ、予定より 2 分以上遅れた回(スリープなど)は発信しません。
  • CallTable.json がまだないときは、各時 01 分・番号 $TestNumber・すべて OFF で作ります。旧版の $CallTimes があれば、その時刻の行を ON にして有効にします(移行用)。

発信試験の成否と受信レベル

  • 1 回の試験は「発信直前の AT+CSQ → ATD<番号>;(通話中も AT+CSQ)→ ATH → 切断直後の AT+CSQ」です。
  • 送信中に端末が干渉を受けていないかを見るのが目的なので、通話中の rssi・BER を直前・直後と比べられるようにしています。画面の「差」(通話中の平均 − 直前)が大きなマイナスなら、送信中に受信が下がっています。
  • IsatPhone 2 は、失敗しても ATD に OK を返し、NO CARRIER も出しません。 代わりに、発信中に独自の通知(+SKCPI・+SKCCSI・+SKGPSPOSI・+CIEV)を自分から送ってきます。AtIo.exe は待っている間に受け取った文字をすべて出力するので、これらは新しいコマンドを送らなくても応答に入っています。
  • 判定は、区切り行で分けた「ATH より前」の部分で行います。順に、COM のエラー → ATD の最初の応答が OK でない → ATH より前の切断の通知(+SKCCSI 状態 6 / +SKCPI 段階 1)→ ATH より前の NO CARRIER など → 独自通知はあるのに回線割当(段階 4)まで進まない、のどれかなら失敗です。ただし、経過通知(呼出音)まで進んだあと理由 16・18・19 で切れたものは、呼は成立していたので成功とします。
  • ATH のあとに来る切断の通知(理由 16 など)は、こちらが切ったものなので判定に使いません。
  • 独自通知を出さない機器では、これまでどおり ATD の応答(OK なら成功)で判定します。
  • 切断の通知より後に送った通話中の AT+CSQ は、通話中の値に数えません(切れたあとは送信していないため)。
  • 通話中の AT+CSQ が ERROR を返しても、発信の成否には影響しません。
  • 通知の意味は公開資料がなく、実機の記録からの推定です(at-command-table.md の「IsatPhone 2 の独自通知」)。
  • 送信レベルは AT コマンドでは取れないので、記録するのは受信レベル(rssi)と BER です。
  • 通話中の値の平均・最小(rssi)、最大(BER)は、99(不明)を除いて計算します。
  • 同じ分に 2 度は発信しません。発信の直後には、いつもの取得(AT+CSQ・AT+CREG?)を 1 回行います。

受信グラフは横スクロールで過去を見る

  • 受信グラフ(監視用)には $HistoryHours(既定 72 時間 = 3 日)分の点を持ちます。点の数は「時間 × 3600 ÷ 取得周期 + 1」(3 分周期・3 日なら 1441 点、上限 3000 点)。旧版の $HistoryMax は使いません。
  • 起動時は、先月と今月の CSV から $HistoryHours 時間以内の行を読んで復元します(月をまたいでも途切れません)。
  • 画面では、グラフの横幅を「点の数 × 6px」(3 日で約 8,600px)にして横スクロールで見せます。Chart.js の時間軸(日付ライブラリが必要)は使わず、横軸は取得した順に並べ、ラベルを「時刻」と「月/日」の 2 段にしています。Monitor が止まっていた時間は詰めて描かれるので、ラベルの日時で確かめてください。
  • 縦軸の目盛りがスクロールで見えなくならないよう、描画のたびにグラフの左端(縦軸の目盛りの部分)を別の canvas に写し、左に重ねて固定しています。
  • 更新のたびに右端に合わせるのは、右端(最新)を見ているときだけです。過去を見ている途中は位置を動かしません。

データの保存先と、過去のデータのまとめ

  • データ(受信ログ・発信試験の CSV・試験ログ・events.csv・calltable_history\)の保存先は Config.ps1 の $LogDir です。相対ならこのフォルダの下、絶対(D:\...・\\server\share\...)ならそのままです([IO.Path]::IsPathRooted で判断)。画面が読む data.js・trend.js・CallTable.json は、画面と同じ app\ に置きます。
  • 過去のデータは Merge.ps1(Merge.bat)で保存先にまとめます。Monitor は CSV に書き足し続けるので、まとめは Monitor を止めて行います(Global\CsqWatch の Mutex があれば止まる)。
  • まとめ方:元のフォルダの下を探し、csq_/isat_/call_YYYYMM.csv の各行を、行の日時の月のファイルに振り分けます。保存先の行と合わせて、まったく同じ行は 1 つにし、日時(先頭 19 文字)と元の順で並べ直します。同じ日時で中身が違う行は両方残して件数を出します(別の端末のデータの混入に気づくため)。events.csv は日時(そろえたもの)と内容で同じかどうかを決めます。
  • 「何件増えるか」を先に出し、確定するまで書き換えません。書き換える前のファイルは merge_backup\日時\ に、結果は merge_report_日時.txt に残します。書くときは一時ファイルに書いてから置き換えます。
  • まとめたあと Monitor を起動すると、Import-History(受信グラフ)と Write-Trend(評価トレンド)が、まとめたデータから作り直します。長い期間を評価するときは $TrendDays を増やします(15 分ごとなので 31 日で約 3,000 区間)。

監視と評価を分ける (評価トレンド)

  • 監視は 3 分ごとの全点を 3 日分。評価は 1 週間単位なので、全点を描くと点が多すぎて重く、canvas の幅の上限にも近づきます。そこで評価用には、Monitor が $TrendDays(既定 7 日)分の受信ログを 15 分ごとにまとめた trend.js を別に作ります(平均・最小・最大・BER の最大・取得失敗の数・圏外の数)。1 週間で 673 区間ほどなので、画面幅に収まり、軽く動きます。
  • trend.js には、同じ期間の発信試験の結果と変化のコメントも入れます。作り直すのは 10 分ごと・発信試験のあと・コメントを取り込んだあとです。data.js は軽いまま(3 秒ごとの読み直し)、trend.js は画面が 1 分ごとに読み直します。
  • まとめた区間は、データがなくても時間どおりに並べます。Monitor が止まっていた時間は空白になるので、止まっていたことが見てわかります(受信グラフは取った順に並べるので、止まっていた時間は詰めて描かれます)。
  • 月をまたぐ期間は、該当する月の CSV をすべて読みます。

変化のコメント

  • logs\events.csv(UTF-8 BOM 付き)に Timestamp,Text,Id の形で残します。Id は画面から足したときの保存日時で、画面が「反映済み」を確かめるのに使います。メモ帳で足した行は Id が空でもかまいません。
  • 画面の「コメントを追加」は、タイムテーブルと同じく csqwatch_event.json をダウンロードとして保存し、Monitor が 5 秒ごとに受け取り先を探して取り込みます。内容の改行は空白に、, は 、 に置き換え、200 文字までにします。一覧から直す・消すときは、JSON に元の日時と内容(old)を入れ、Monitor が events.csv の該当行を置き換える・消す。events.csv を直接直したときは、Monitor が更新日時の変化を 5 秒ごとに見て、すぐ trend.js を作り直します。取り込んだファイルは logs\calltable_history\ へ移します。
  • コメントは評価トレンドと受信グラフの両方に縦線で描きます(Chart.js のプラグインで、グラフを描いたあとに線とラベルを重ねる)。受信グラフでは、コメントの時刻以前でいちばん近い点の位置に引きます。

更新停止の検知

data.js に取得周期(intervalSec)を含め、画面側で最終更新時刻と比べます。周期の 2 倍 + 10 秒を超えると STALE 表示にします。 Monitor の停止、COM の切断、data.js が出力されないとき、のいずれにも気づけます。

試験ログ

不具合の解析とデータ取得の検証のため、logs\test_YYYYMMDD.log に 1 行ずつ記録します。書式と見かたは README の「試験ログ」を参照してください。

  • 1 行ごとにファイルを開いて追記し、閉じます。強制終了や PC の再起動の直前まで残ります。
  • 応答はログ用に整形します(PowerShell 5.1 が外部プログラムのエラー出力に付ける「発生場所 …」などの飾りを除く)。判定には整形前の応答を使います。
  • メインループを try { } finally { } で囲み、Ctrl+C で止めたときに STOP を残します。× ボタンで閉じた・再起動・強制終了では残らないので、「STOP がない = 外部要因」と見分けられます。
  • 予期しないエラーは trap で ERR UNHANDLED(行番号付き)を残してから止まります。

文字コードの規約

.ps1 .cs probe_commands.txt は UTF-8(BOM 付き)・CRLF です(.editorconfig と .gitattributes で固定)。 BOM がないファイルは、日本語環境の Windows PowerShell 5.1 と csc.exe が ANSI(cp932)と誤読し、日本語の文字列が壊れます。 .bat は cmd が cp932 を使うため、ASCII のみにしています(日本語を入れないでください)。 .md は UTF-8(BOM なし)・LF です。説明書 app/manual.html は MD から tools\build_manual.bat(Build-Manual.ps1、PowerShell 5.1 のみ)で生成します(直接編集しない)。

補足

  • Common.ps1 の Invoke-At は PowerShell から AtIo.exe を呼びます。コマンド文字列に " を含むもの(AT+CGDCONT=1,"IP","apn" など)は、PowerShell 5.1 のネイティブコマンド引数の扱いで壊れるため、現状は送れません。
  • -Mock の疑似応答は Common.ps1 の Get-MockResponse にあります。$Extras で新しいコマンドを試すときは、ここに疑似応答を足すと画面で確認できます。疑似データは IsatPhone 2 の実測に近い範囲(rssi 20〜50)で動きます。
  • 実行環境は Windows 11 標準の PowerShell 5.1・.NET Framework 4.x・Edge だけです。インストールも管理者権限も要りません。

AT コマンドの対応範囲

Author: yuichi(更新 2026-10-28)

コマンドごとの意味・応答の形・確認結果は、at-command-table.md にまとめてあります。

現状でわかっていること

  • 標準コマンド(ITU-T V.250 と 3GPP TS 27.007)は、多くのモデム機器で共通に使えます。このツールが周期的に使っているのは AT+CSQ(信号強度)と AT+CREG?(登録状態)、試験発信では ATD と ATH です。
  • 機器によって、対応しているコマンドの範囲と、値の目盛りが違います。新しい機器では、まず Probe.bat で対応状況を調べ、AT+CSQ=? の応答から目盛りの最大値を確かめて Config.ps1 の $RssiMax に設定します。

Inmarsat IsatPhone 2(2026-10-14、実機で確認)

  • IsatPhone 2 固有の AT コマンド仕様は、公開情報では見つかっていません。 対応範囲は、実機の Probe で調べた結果がすべてです。
  • 取扱説明書によると、USB 接続でモデムとして使えます(「IsatPhone 2 Modem」として COM ポートが現れる)。実際にはメーカーの USB ドライバーが必要で、正しく入ると「IsatPhone 2 Command」「IsatPhone 2 Data」として認識されます。ドライバーなしでは COM ポートが見えても通信できません。
  • 標準の主なコマンド(AT+CSQ・AT+CREG?・AT+COPS?・AT+CPAS・AT+CPIN? など)は使えます。
  • AT+CSQ の rssi は 0〜55(標準は 0〜31)で、GSM の dBm 換算は使えません。
  • AT+CBC は使用禁止です。 応答がないうえ、その後しばらく(Probe では約 30 秒)ほかのコマンドにも応答しなくなります。
  • AT+CLAC(対応コマンドの一覧)は使えません。パケット系(AT+CGREG?・AT+CGATT?)も未対応です。
  • AT+CLCC と GPS 系は、AT+CBC の影響で結果が取れていないので、AT+CBC を外して調べ直す必要があります。
  • 発信中は、独自の通知(+SKCPI・+SKCCSI・+SKGPSPOSI・+CIEV)を自分から送ってきます。失敗しても ATD は OK を返すので、成否はこの通知で判定します(詳しくは at-command-table.md の「IsatPhone 2 の独自通知」)。
  • 発信試験の実行中に送った AT+CSQ(--- during)にも応答が返ることを確認しました(2026-10-28、値 52〜53)。ただし、その回が通話の確立中だったか、網から切断されたあとだったかは、まだ確かめていません。

実機で調べる — Probe

Probe.bat

probe_commands.txt のコマンドを順に送り、OK / ERROR / NO RESPONSE / IO ERROR の一覧と、各コマンドの生の応答を probe_YYYYMMDD_HHMMSS.txt に保存します。1 コマンドあたりの待ち時間は 5 秒です。

  • Monitor.bat を止めてから実行してください。COM ポートは同時に 1 プログラムしか使えません(Monitor どうしの二重起動は自動で防ぎますが、Probe との同時実行は防ぎません)。
  • まず AT+CLAC(対応コマンドの一覧)の結果を見てください。対応している機器なら、受け付けるコマンドがすべて出ます(IsatPhone 2 は未対応)。
  • 調べたいコマンドは probe_commands.txt に 1 行足します。
  • 読み出し・問い合わせ系だけにしてください。ATD(発信)、ATZ / AT&F(リセット)、AT+CFUN(機能切替)、AT+CGPS=1 のような起動・設定系は入れないこと。
  • AT+CGSN はシリアル番号が出るため、既定でコメントアウトしてあります。結果ファイルを共有するときは注意してください。

結果の読み方の注意

  • NO RESPONSE が続けて並んでいるときは、それぞれが未対応なのではなく、その手前のコマンドで機器が固まっている可能性があります。未対応のコマンドなら、普通はすぐに ERROR や +CME ERROR が返るからです。最初に NO RESPONSE になったコマンドを外して、もう一度調べてください(IsatPhone 2 の AT+CBC がこの例です)。

  • 機器が固まるコマンドを見つけたら、probe_commands.txt で # を付けてコメントにし、理由と日付を書いておきます(削除せずに残すと、記録になります)。

    # AT+CBC    使用禁止: IsatPhone 2 が無応答になり後続も返らなくなる (2026-10-14 確認)
  • +CME ERROR: <n> の番号が 3GPP の範囲外(IsatPhone 2 の 600 など)のときは、メーカー独自の意味です。

項目を画面に足す

Probe で OK が返ったコマンドを、Config.ps1 の $Extras に 1 行足します。

$Extras = @(
    @{ Name = 'Operator'; Cmd = 'AT+COPS?'; Regex = '\+COPS:\s*\d+,\d+,"([^"]*)"' }
)

Regex の最初のかっこ ( ) に入った部分が、カードの値になります。

  • $Extras のコマンドは、取得周期ごとに AT+CSQ・AT+CREG? に続けて送ります。機器を固まらせるコマンドを入れると、監視そのものが止まります。 Probe で OK がすぐに返ることを確かめたものだけにしてください。
  • 送受信の内容は試験ログ(logs\test_YYYYMMDD.log)に残り、値を取り出せなかったときは WARN <Name> 解析失敗 が出ます。

GPS の衛星数・信号強度

  • 標準の AT コマンドには、GPS の衛星数や C/N0 を返すものがありません。メーカー独自の拡張になります。
  • IsatPhone 2 は GPS 受信機を内蔵していますが、USB のモデムポートから情報を出せるかどうかは、公開情報では確認できていません。
  • 試すルートは 2 つです。
    1. AT コマンドの独自拡張。probe_commands.txt に他社モジュールでの例を入れてあります。IsatPhone 2 では AT+GPSINFO が +CME ERROR: 600 を返し、ほかは AT+CBC の影響で結果が取れていません。
    2. 別の COM ポートに流れる NMEA 出力。デバイスマネージャーで、COM ポートが複数ないか確認します(IsatPhone 2 は「Command」と「Data」の 2 つが現れます)。$GPGSV 文から、見えている衛星の数と SNR が分かります。NMEA は連続で流れてくるため、AtIo.exe(1 コマンド 1 応答)とは別の読み取り処理が必要です。

<rssi>(AT+CSQ の 1 つ目の値)

<rssi>受信電力
0-113 dBm 以下
1-111 dBm
2 〜 30-109 〜 -53 dBm(2 dB 刻み)
31-51 dBm 以上
99不明、または測定できない

この表と換算式 dBm = -113 + 2 × <rssi>(0〜31)は、GSM の定義です。

IsatPhone 2 では使えません。 AT+CSQ=? の応答が (0-55,99),(0-15,99) で、rssi は 0〜55、ber は 0〜15 の独自の目盛りです(2026-10-14 確認)。実測は屋内・外部アンテナで 37〜38 でした。GSM の式に当てはめると -39 dBm のようなありえない値になるため、このツールは dBm に換算せず、生の値を 値 / 最大値(例 37 / 55)で表示します。最大値は Config.ps1 の $RssiMax です。値と実際の受信品質(C/N0 など)との対応はまだわかっていません。

端末が 99 を返したときはグラフ上で 0 として描き、画面に 圏外 (99) と出します。端末から値を取れなかったとき(取得失敗)は、グラフの線を途切れさせ、圏外 とは区別します。

<ber>(AT+CSQ の 2 つ目の値)

0〜7 がビット誤り率の段階、99 が不明です(GSM の定義。IsatPhone 2 は 0〜15)。機器によっては常に 99 を返します(このツールの Ber 表示は、返ってきた値をそのまま出します)。

<n>(AT+CREG? の 1 つ目の値)

<n>意味

7. 使い方の例

AtIo.exe は、コマンドを引数で渡して 1 回だけ送ります。

AtIo.exe COM3 115200 "AT+CSQ" 3
AtIo.exe COM3 115200 "ATD+819012345678;" 20 "ATH"
AtIo.exe COM3 115200 "ATD+819012345678;" 20 "ATH" "AT+CSQ" 5

書式は AtIo.exe <ポート> <ボーレート> <コマンド> [待ち秒] [後続コマンド] [通話中のコマンド] [通話中の間隔秒] です。3 行目は、発信して OK を受けてから 5 秒ごとに AT+CSQ を送り、20 秒後に ATH で切ります。

引数の説明は、AtIo.exe -HELP でも表示できます。

画面に項目を足すには、Config.ps1 の $Extras に書きます(Probe で OK が返ったコマンドだけ)。

$Extras = @(
    @{ Name = 'Operator'; Cmd = 'AT+COPS?'; Regex = '\+COPS:\s*\d+,\d+,"([^"]*)"' }
)

IsatPhone 2 では、この例で 90111 が表示されます。AT+CBC(バッテリー)は IsatPhone 2 では使わないでください。

Git 経由で社内 PC に導入する

Author: yuichi(更新 2026-10-21)

USB メモリを持ち込めない環境向けの手順です。

開発側の PC ──push──► GitHub ──clone / ZIP──► 社内 PC

AtIo.exe はリポジトリに含めません。社内 PC で build.bat を実行して作ります(csc.exe は Windows 標準なので、追加のインストールは要りません)。

社内 PC に必要なものは、Windows 11 に最初から入っているものだけです(PowerShell 5.1・.NET Framework 4.x・Edge)。インストールも管理者権限も要りません。

1. GitHub に置く(開発側 PC・初回だけ)

  1. GitHub で空のリポジトリを作ります(README や LICENSE は追加しない)。名前の例は csqwatch です。

  2. csqwatch-repo フォルダの中で実行します。

    git init -b main
git config user.name  "あなたの名前"
git config user.email "<ID>+<ユーザー名>@users.noreply.github.com"
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/<ユーザー名>/csqwatch.git
git push -u origin main

    メールアドレスを公開したくないときは、上の users.noreply.github.com の形(GitHub の設定画面の Email に表示されます)を使います。

  3. push の前に、git status と git ls-files で次のものが含まれていないことを確認します(.gitignore で除外済みです)。
    • Config.ps1(COM 番号・発信先)、CallTable.json(発信試験のタイムテーブル。着信番号が入る)
    • logs\(CSV・試験ログ・events.csv・monitor_running.txt)、data.js、trend.js、probe_日時.txt(実機の値や機器の情報が入ります)
    • profile_<ブラウザ名>\(監視画面用のブラウザプロファイル)
    • AtIo.exe

公開リポジトリにする場合の注意: コミットしたものは、誰でも見られます。社内の名称・電話番号・機器の情報を、ファイルに書き込まないでください。現在のファイルには、ダミーの電話番号(+819012345678)しか入っていません。

2. 社内 PC に入れる

2-A. Git が入っている場合

git clone https://github.com/<ユーザー名>/csqwatch.git
cd csqwatch\app
build.bat

更新するときは、次のとおりです。

cd csqwatch
git pull

AtIo.cs が変わったときだけ、app\build.bat を実行し直します。 Config.ps1・CallTable.json・logs\・profile_<ブラウザ名>\・AtIo.exe は Git の管理外なので、git pull で上書きされたり消えたりしません。

2-B. Git が入っていない場合(Windows 11 の標準機能だけ)

ブラウザで、リポジトリのページの Code → Download ZIP を選びます。コマンドで取るときは、次のとおりです。

curl.exe -L -o csqwatch.zip https://github.com/<ユーザー名>/csqwatch/archive/refs/heads/main.zip
Unblock-File .\csqwatch.zip
Expand-Archive .\csqwatch.zip -DestinationPath .

(Unblock-File と Expand-Archive は PowerShell のコマンドです。curl.exe はコマンドプロンプトでも使えます。)

  • 展開すると csqwatch-main というフォルダができます。その中の app を使います。
  • Unblock-File を忘れないでください。 インターネットから取った ZIP は「ブロック」の印が付いていて、展開したファイルまで引き継ぎます。そのまま .bat を開くと、セキュリティの警告が出ます。ZIP のプロパティで「許可する」にチェックを入れても同じです。
  • 更新するときは、監視(Monitor.bat)を止めてから、新しい ZIP を取り直し、展開した app の中身を前回のフォルダへ上書きコピーします。Config.ps1・CallTable.json・logs\・profile_<ブラウザ名>\ は ZIP に入っていないので、残ります。AtIo.cs が変わったときは、build.bat で AtIo.exe を作り直してください(2026-10-26 の発信試験の追加で変わっています)。

2-C. 旧名(IsatMon)から入れ替える場合

以前の IsatMon を使っていた PC では、次の順に入れ替えます。詳しくは README の「旧名(IsatMon)からの移行」を参照してください。

  1. 旧版の監視を止める(旧版と新版は、互いの二重起動を検出できません)
  2. 新しい app の中身を上書きコピーし、build.bat で AtIo.exe を作る
  3. 古い IsatIo.exe と、使わなくなった Dashboard.bat・Dashboard.ps1・edge_profile\ があれば削除する
  4. Monitor.bat で起動する(今月の旧 CSV isat_YYYYMM.csv からグラフを復元します)

3. 動作確認

cd app
build.bat          → BUILD OK: AtIo.exe
